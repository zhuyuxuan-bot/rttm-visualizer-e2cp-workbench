# E2CP RTTM 可视化标注器

这是面向《三体》对话校准工作的 RTTM 可视化标注工具。它把视频/音频、RTTM 说话人时间段、SRT 字幕、声纹/人脸候选证据放到同一个界面中，帮助标注员完成说话人校对、台词校对、漏句插入、删除多余句、保存工程进度和导出结果。

## 在线使用

如果仓库已启用 GitHub Pages，可以直接打开：

```text
https://zhuyuxuan-bot.github.io/rttm-visualizer-e2cp-workbench/
```

如果页面暂时打不开，请在 GitHub 仓库的 `Settings -> Pages` 中确认来源选择为 `GitHub Actions`，然后等待 `Deploy GitHub Pages` 工作流完成。

## 三种工作模式

工具顶部提供三个模式，按下面的顺序使用：

1. `准备`：选择剧集，上传视频/音频、主 RTTM、SRT、subseg JSON 和可选参考 RTTM。
2. `标注`：标注员逐句确认说话人、台词和时间，处理漏句、多余句并保存标注工程。
3. `检查`：检查人导入标注员交付的工程 JSON，逐句通过或提交带原因的修改建议；检查建议不会直接覆盖原始标注。

最简协作流程：

```text
标注员：准备文件 -> 标注 -> 保存进度 JSON
检查人：导入标注工程 -> 检查 -> 导出复核包
标注员：导入复核包 -> 处理检查反馈 -> 再次交付
检查人：开启下一轮复核 -> 确认已解决 -> 完成
```

## 标注时需要上传什么

每一集至少需要：

- 视频或音频：例如 `ep17.mp4`、`17.wav`。
- 主 RTTM：当前要编辑的说话人时间段文件，例如 `EP17.rttm`。
- SRT：字幕文件，例如 `ep17_for_review.srt`。

强烈建议同时上传：

- `subseg_match_results.json`：声纹/人脸候选证据，用于辅助判断说话人。
- 参考 RTTM：只有在该集有可靠标准 RTTM 时才上传，用于对照，不要误当作主 RTTM。

## 前 15 集和 16-30 集的区别

- 前 15 集：部分集有三模态融合结果，可上传“标准 RTTM”或较可靠 RTTM。
- 第 08、12、15 集以及 16-30 集：通常没有可直接当标准答案的三模态融合 RTTM，应上传“初始标注 RTTM”，再人工校对。
- 工具界面会提示当前集应使用“标准 RTTM”还是“初始标注 RTTM”，避免把草稿误当标准答案。

## 标注员快速规则

- 台词正确、说话人正确、时间基本正确：点击 `通过检查`。
- 说话人错误：点击正确说话人，状态自动进入已修正。
- 台词文本错误：只在文本输入框中改错字、漏字或错词。
- 时间不准：拖动时间轴片段边界，或填写开始秒/结束秒。
- 视频里有声音但列表里没有：用波形框选范围，点击 `插入漏句`。
- 列表里有一句但视频里不存在：标记为删除，不要手动删原始文件。

更多细节见：[完整使用说明书](docs/USER_MANUAL_ZH.md)。

## 检查模式

检查人收到标注员导出的工程 JSON 后，可以在顶部切换到 `检查`：

1. 点击 `导入标注工程`，选择标注员交付的 `*_review_project.json`。
2. 如果当前浏览器还没有本集媒体，先到 `准备` 上传对应视频或音频，再返回 `检查`。
3. 在右侧完整台词列表逐句复核；点击任意一行会同步跳转播放位置。
4. 正确时点击 `通过本句`；发现错误时选择问题类型、填写原因，并在右侧“检查建议”中给出说话人、台词或时间修改值。
5. 点击 `提交修改建议` 后，原始值不会被覆盖，检查建议和操作者、时间、原因会写入不可删除的操作记录。
6. 使用 `保存复核进度` 生成可继续检查的文件，使用 `导出复核包` 把标注工程、复核轮次和完整留痕一并交回标注员。

标注员导入带有反馈的复核包后，可在 `标注` 模式看到“检查人反馈”，选择接受建议并回改，或保留当前值并回复。双方的每次操作都会保留，便于下一轮复核追踪。

### 检查页面怎么用

- 左侧视频和波形：播放当前句，核对说话内容、说话人和时间边界。
- 右上完整台词列表：显示全剧台词与检查状态，点击任意行可跳转到对应时间。
- 右中当前句检查：左边保留原始标注，右边填写检查建议；可同时指出说话人、台词和时间问题。
- 问题类型与原因：发现问题时必须选择类型并填写原因，方便标注员理解和回改。
- 底部操作记录：按时间追加保存检查人和标注人的每次操作，不允许删除或覆盖。

检查人中途退出前使用 `保存复核进度`；本轮检查结束后使用 `导出复核包`。不要把 `导出 RTTM` 当作复核交接文件，因为 RTTM 不包含台词、问题原因和操作记录。

## 保存进度

工具支持本地自动草稿，但长期保存请使用：

- `保存进度 JSON`：保存完整标注工程，文件通常命名为 `*_review_project.json`，适合下次继续、审计修改、生成最终融合 JSON。
- `导入工程 JSON 继续`：选择上一次保存的 `*_review_project.json`，恢复片段、说话人、状态、漏句、删除句和备注。
- `导出 RTTM`：只保存当前说话人时间段，适合下游说话人时间轴处理。

推荐每完成一段标注后点击一次 `保存进度 JSON`。如果中途退出浏览器，下一次打开工具后先点击 `导入工程 JSON 继续`，再重新上传本集视频/音频用于播放，就可以从上次进度继续。浏览器里的本机自动草稿只适合同一台电脑、同一浏览器的临时恢复，不建议当作长期保存方式。

### 下一次继续标注的最小步骤

1. 打开工具。
2. 点击 `导入工程 JSON 继续`。
3. 选择上一次保存的 `*_review_project.json`。
4. 按界面提示重新上传本集视频/音频、必要时上传 subseg JSON。
5. 从右侧当前片段或台词列表继续校对。

## 导出前检查

导出前请确认：

- `pending` 数量是否为 0。
- 是否还有 `uncertain` 或 `UNKNOWN`。
- 人工插入漏句是否都填写了说话人和文本。
- 标记删除的句子是否已经复核。
- 起止时间是否存在异常或重叠。

工具会在导出前报告中提示这些风险。
