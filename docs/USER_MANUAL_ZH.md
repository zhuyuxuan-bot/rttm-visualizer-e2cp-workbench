# RTTM 可视化标注器使用说明书

本文档面向第一次参与《三体》说话人和台词校对的标注员。目标是让标注员只需要准备视频、RTTM、SRT 和可选的候选证据文件，就能使用 RTTM 可视化标注器完成审查、修正、漏句插入、保存进度和导出结果。

## 1. 工具用途

RTTM 可视化标注器用于把视频、说话人时间段、字幕文本和候选识别证据放到同一条时间轴上，帮助人工判断：

1. 这一句台词是否真的存在。
2. 台词文本是否正确。
3. 说话人是否正确。
4. 起始时间和结束时间是否准确。
5. 是否存在字幕或说话片段遗漏。
6. 是否存在视频中不存在的多余句子。

工具最终服务于三模态融合 JSON 或双模态校对结果的人工标准化，不建议再直接手改原始 CSV 或 JSON。

## 3. 每集需要准备的文件

### 3.1 必需文件

标注任意一集至少需要：

1. 视频或音频文件，例如 `ep17.mp4`。
2. 主 RTTM 文件，例如 `EP17.rttm`。
3. SRT 字幕文件，例如 `ep17_for_review.srt`。

### 3.2 强烈建议上传的文件

1. `subseg_match_results.json`：声纹和人脸候选证据，用于显示 `top_5_speakers`、`top_5_faces` 等候选信息，辅助判断说话人。
2. 参考 RTTM：如果某一集已经有标准或较可靠 RTTM，可作为参考 RTTM 上传，用于对照或 DER 诊断。

### 3.3 前 15 集和 16-30 集的差别

前 15 集部分剧集有三模态融合结果，可以由其生成初始 RTTM 或标准 RTTM。第 08、12、15 集如果没有三模态融合结果，应按初始标注 RTTM 处理。

16-30 集通常只有双模态结果，不能直接当作标准三模态结果。标注时应上传由双模态结果或现有识别结果生成的“初始标注 RTTM”，再结合视频、SRT 和人工检查逐步修正。

请注意区分：

1. 标准 RTTM：已经人工确认或高可信的参考文件。
2. 初始标注 RTTM：机器识别或融合生成的待校对文件。
3. 参考 RTTM：只用于对照，不应误当作当前正在编辑的主 RTTM。

## 4. 推荐上传顺序

1. 选择剧集。
2. 上传视频或音频文件。
3. 上传当前要编辑的主 RTTM 文件。
4. 上传 SRT 字幕文件。
5. 上传 `subseg_match_results.json`。
6. 如有参考文件，再上传参考 RTTM。

如果上传 RTTM 时误入“参考 RTTM”，请检查界面上的上传入口名称。当前要编辑的 RTTM 必须放在“RTTM / 初始标注 RTTM / 主 RTTM”入口，不要放到“参考 RTTM”入口。

## 5. 主界面区域说明

### 5.1 顶部状态栏

顶部状态栏用于查看当前工作状态，通常包括：

1. 当前剧集。
2. 视频、RTTM、SRT、subseg 是否已加载。
3. 当前标注进度。
4. 导出 RTTM。
5. 导入工程 JSON 继续。
6. 保存进度 JSON。

“导出 RTTM”导出的是当前时间轴中的说话人片段，可用于后续流程继续生成标准答案。

“导入工程 JSON 继续”用于选择上一次保存的 `*_review_project.json`，恢复片段、说话人、状态、插入句、删除句和备注。

“保存进度 JSON”导出的是完整工程状态，包含媒体信息、片段、说话人、状态、插入句、删除句、备注等，适合保存进度和恢复工程。

### 5.2 资源面板

资源面板用于加载和替换文件。标注阶段它可以收起，避免占用主工作区。

资源面板中通常包含：

1. 剧集选择。
2. 视频或音频文件状态。
3. RTTM 文件状态。
4. SRT 文件状态。
5. subseg JSON 上传。
6. 参考 RTTM 上传。
7. 波形检查。
8. 文件替换按钮。

如果文件缺失、解析失败或替换失败，应先回到资源面板解决。

### 5.3 视频和波形时间轴

中间区域是核心标注区：

1. 上方显示视频画面。
2. 下方显示播放控制、速度、缩放和时间轴。
3. 波形用于判断是否存在遗漏说话。
4. 红色播放线表示当前视频播放位置。
5. 彩色块表示不同说话人的 RTTM 片段。
6. 字幕块表示对应 SRT 台词。

如果看到波形上有明显声音，但下方没有对应字幕或片段，需要检查是否为漏句。

### 5.4 右侧台词列表

右侧台词列表显示整集所有台词。每行通常包含：

1. 序号。
2. 开始时间。
3. 结束时间。
4. 说话人。
5. 状态。
6. 台词文本。

播放视频时，右侧列表会跟随当前播放位置高亮对应台词。点击任意一行，应跳转到对应时间并设为当前校对片段。

### 5.5 当前片段校对区

当前片段校对区用于处理正在选中的一句话。它通常包含：

1. 当前时间范围。
2. 当前说话人。
3. 状态。
4. 开始秒和结束秒。
5. 台词文本输入框。
6. 一键更改说话人。
7. 漏句插入。
8. 删除或标记不存在。
9. 通过检查。
10. 下一条待处理。

## 6. 标注状态定义

建议统一使用以下状态：

1. `pending`：尚未检查。
2. `checked`：文本正确、说话人正确、时间基本正确。
3. `corrected`：已人工修正，例如说话人、文本或时间有改动。
4. `inserted`：人工新增的漏句。
5. `deleted`：视频中不存在，人工标记删除。
6. `uncertain`：无法确认，需要后续复核。

## 7. 基本校对规则

### 7.1 正确台词

如果视频中确实有这句话，台词文本正确，说话人也正确：

1. 选中该行或播放到该片段。
2. 点击“通过检查”。
3. 工具把状态设为 `checked`。
4. 继续下一条待处理。

这种情况不需要手动输入文字。

### 7.2 说话人错误

如果台词文本正确，但说话人错误：

1. 选中该片段。
2. 在“一键更改说话人”中点击正确说话人。
3. 如果候选中没有该说话人，使用“新增说话人”添加。
4. 状态应设为 `corrected`。
5. 确认时间轴颜色块已经变为新说话人对应颜色。

### 7.3 台词文本错误

如果说话人正确，但台词文本错误：

1. 选中该片段。
2. 在台词文本输入框中输入正确文本。
3. 状态设为 `corrected`。
4. 保存或导出工程 JSON。

只有文本错误、漏字、错字、错词时才需要手动敲键盘。

### 7.4 起止时间错误

如果文本和说话人正确，但时间不准：

1. 在时间轴上拖动片段边界，或在右侧输入开始秒、结束秒。
2. 借助波形和视频确认范围。
3. 状态设为 `corrected`。

### 7.5 视频中不存在的句子

如果列表中有一句话，但视频里不存在：

1. 选中该片段。
2. 使用“删除”或“标记不存在”功能。
3. 状态设为 `deleted`。
4. 不要直接从原始文件中手动删除行。

这样可以保留审计记录，避免后续无法判断句子为什么消失。

## 8. 漏句处理规则

漏句是指视频或音频中有人说话，但 SRT、RTTM 或台词列表里没有对应句子。

推荐处理流程：

1. 在波形上找到疑似漏句的声音峰值。
2. 拖选或点击确定开始时间和结束时间。
3. 在漏句插入区填写说话人。
4. 如果能听清文本，填写台词文本。
5. 如果暂时听不清，文本可以先留空或写简短备注，状态设为 `inserted` 或 `uncertain`。
6. 点击“插入漏句”。
7. 确认新片段立刻出现在时间轴和右侧台词列表中。

漏句插入后，后续导出 RTTM 和工程 JSON 都应该包含这条新增记录。

## 9. subseg_match_results.json 的作用

`subseg_match_results.json` 是声纹和人脸候选证据文件。它通常来自前处理或服务器识别结果。

上传后的用途：

1. 为当前片段显示声纹候选说话人。
2. 为当前片段显示人脸候选人物。
3. 辅助判断当前说话人是否可能识别错误。
4. 帮助新增或修正说话人。

它不是最终标注结果，也不应直接覆盖人工判断。人工标注仍以视频、音频、字幕和上下文为准。

如果解析失败，常见原因是文件里存在非法 JSON 值，例如 `NaN`。工具会尽量自动清洗；如果仍失败，需要先把 `NaN` 转换为 `null`，再上传。

## 10. 保存进度

推荐保存方式：

1. 标注过程中会自动写入本机草稿，适合短时间内防止浏览器意外关闭。
2. 每完成一段重要校对后，点击“保存进度 JSON”。
3. 工程 JSON 文件通常命名为 `*_review_project.json`，也可以另存为 `ep17_annotation_project_20260609.json`。
4. 下次打开工具时，优先点击“导入工程 JSON 继续”，而不是重新从原始 RTTM 开始。
5. 工程 JSON 恢复后，仍需重新上传视频或音频文件，因为浏览器不能长期保存本地媒体文件路径。

下次继续标注的最小步骤：

1. 打开工具。
2. 点击“导入工程 JSON 继续”。
3. 选择上一次保存的 `*_review_project.json`。
4. 重新上传本集视频/音频，用于播放、波形和时间轴校对。
5. 如果需要候选证据，再上传 `subseg_match_results.json`。
6. 从右侧当前片段或台词列表继续校对。

如果工具支持本地自动草稿：

1. 自动草稿用于临时恢复上次浏览器会话。
2. 不建议只依赖浏览器草稿作为长期保存。
3. 长期保存应以导出的工程 JSON 为准。

## 11. 导出结果

### 11.1 导出 RTTM

导出 RTTM 用于保存当前说话人时间段。它适合给后续自动流程使用，例如：

1. 重新计算 DER。
2. 生成三模态或双模态融合结果。
3. 作为下一轮标注的初始 RTTM。

RTTM 主要保存说话人和时间段，不适合作为完整人工校对记录。

### 11.2 导出工程 JSON

导出工程 JSON 用于保存完整标注工程。它应包含：

1. 片段时间。
2. 说话人。
3. 台词文本。
4. 状态。
5. 插入句。
6. 删除句。
7. 备注。
8. 候选证据引用。

这是最适合恢复进度、审计修改和继续标注的格式。

### 11.3 导出前检查

一整集完成后，导出前应检查：

1. 是否仍有 `pending`。
2. 是否仍有 `uncertain`。
3. 是否存在未填写文本的 `inserted` 漏句。
4. 是否存在大量 `deleted` 需要复核。
5. 是否还有明显说话人错误。
6. 是否有异常时间段，例如开始时间晚于结束时间。
7. 是否有时间重叠或空白异常。

## 12. 一整集标注完成后的后续工作

1. 导出工程 JSON，作为可恢复、可审计的完整标注结果。
2. 导出 RTTM，作为说话人时间段标准结果。
3. 运行导出前检查报告，确认没有 pending、uncertain、异常漏句。
4. 将工程 JSON 和 RTTM 放入该集的标准输出目录。
5. 使用脚本把工程 JSON 转换为最终三模态融合 JSON 或双模态校对 JSON。
6. 对最终 JSON 做格式校验。
7. 抽样回放视频，确认最终 JSON 与视频一致。
8. 使用 git 提交标注结果和必要说明。

## 13. 常见问题

### 13.1 为什么看不到波形？

常见原因：

1. 视频或音频还没有完成解析。
2. 浏览器没有成功解码媒体。
3. 文件太大，波形生成需要等待。
4. 当前缩放范围太大，波形看起来像一条直线。

建议先确认媒体能正常播放，再等待波形生成完成，必要时放大时间轴查看。

### 13.2 为什么刷新后之前的修改不见了？

如果没有恢复自动草稿或导入工程 JSON，刷新页面可能只会重新加载原始文件。为了避免丢失：

1. 标注过程中定期导出工程 JSON。
2. 下次继续时先导入工程 JSON。
3. 不要只依赖浏览器页面状态。

### 13.3 为什么上传 subseg JSON 解析失败？

如果报错包含 `NaN`，说明文件不是严格合法 JSON。JSON 标准不允许 `NaN`，需要把它替换为 `null`。当前工具会尝试自动清洗常见 `NaN`，但复杂格式仍可能需要人工处理。

### 13.4 为什么右侧列表和视频播放不同步？

可能是关闭了跟随播放，或用户手动滚动后工具暂时尊重人工查看位置。点击“恢复跟随播放”或重新点击当前播放行即可。

### 13.5 为什么有些片段显示没有台词文本？

RTTM 本身只记录说话人和时间，不记录台词文本。工具通常会根据时间匹配 SRT。若 SRT 没有对应时间段，就会显示暂无文本。此时需要人工判断是否为漏句、字幕缺失或时间错位。

## 14. 标注员最小操作清单

每天开始标注前：

1. 打开工具。
2. 选择或上传本集视频。
3. 上传主 RTTM。
4. 上传 SRT。
5. 上传 subseg JSON。
6. 恢复上次工程 JSON 或草稿。

标注过程中：

1. 正确句只点“通过检查”。
2. 说话人错误只点正确说话人。
3. 文本错误才手动修改文本。
4. 时间错误用波形或时间输入修正。
5. 漏句用“插入漏句”。
6. 不存在的句子标记为删除。

结束前：

1. 查看 pending 和 uncertain 数量。
2. 导出工程 JSON。
3. 导出 RTTM。
4. 保存到该集输出目录。
5. 提交 git。

## 15. 命名建议

建议每集输出文件使用统一命名：

```text
ep17_annotation_project.json
ep17_checked.rttm
ep17_export_report.json
```

如果保留多轮版本：

```text
ep17_annotation_project_v01.json
ep17_annotation_project_v02.json
ep17_checked_v02.rttm
```

## 16. 核心原则

1. 不直接手改原始 CSV 或 JSON。
2. 所有人工修改都通过可视化器完成。
3. 文本正确且说话人正确时，只点通过，不敲键盘。
4. 只有文本错误或漏句时才手动输入。
5. 漏句、删除句、修正句必须保留状态。
6. 工程 JSON 是恢复进度和审计的主文件。
7. RTTM 是下游说话人时间段处理的主文件。
8. subseg JSON 是候选证据，不是人工最终答案。
